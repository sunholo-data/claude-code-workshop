# How this workshop teaches

Adapted from learning design for AI tutors: the same ideas, moved from teaching a subject to
teaching a tool.

| # | Principle | Here |
|---|---|---|
| 1 | **The map unlocks, the guide ticks.** | `tree/tree.yaml` is a prerequisite graph. The `workshop-guide` skill marks a node done only when it has seen the node's `proof`, and says why: *"✓ git-safety-net, because you reverted the CLAUDE.md change."* The learner doesn't tick their own boxes. |
| 2 | **Bounded by the frontier.** | The guide offers only nodes whose `needs` are met. Questions beyond the frontier are parked, not answered at length. |
| 3 | **Don't do the exercise for them.** | In this course Claude *does* the work; that is the point. What the guide does not do is drive: it sets the task and checks the proof, and the learner tells Claude what to do. |
| 4 | **Explain on the second ask.** | Pure questioning frustrates. The guide nudges first; asked twice, it explains plainly. Being stuck is not the lesson. |
| 5 | **Ask what they've tried.** | The guide's first response to "it doesn't work" is to ask what was tried and what happened. |
| 6 | **Predict, observe, explain.** | Every lesson starts with *predict what Claude will do*, then run it, then explain the difference. Most of the learning about agents is in the gap. |
| 7 | **Formative, not a scoreboard.** | Progress is per person and private. The facilitator's view is a distribution — where the room is — not a ranking. |
| 8 | **Self-assessment as the survey.** | The pre-session survey *is* the tree: each node's `can` sentence, answered yes / partly / no. The same sheet closes the day. |
| 9 | **Misconceptions are surfaced, not corrected flatly.** | Common ones are listed per node (for example "it remembers yesterday", "it can see my whole computer") and the exercise is built to expose them. |

One consistent loop (principle 6) is used throughout rather than a different teaching model per
lesson; for a short course the consistency matters more than the variety.
