# Clone, branch, push

To work on something shared, you **clone** it (a full copy on your laptop, with its history), make
a **branch** (your own line of changes, so the main version is untouched), and **push** the branch
back to GitHub where others can see it. This is how the team's skills get shared later in the day.

## Do

1. Get the address of your team's skills repository from the facilitator; it is also today's practice repository. In a session on any folder, ask
   Claude: *"Clone <address> into my Documents folder."* Then start a **+ New session** on the
   cloned folder.
2. Ask: *"Make a branch called <your-name>-first-change."*
3. Make one small change and ask Claude to commit it.
4. **Predict:** you ask Claude to push the branch. Will anything ask you to sign in? Will your
   change appear on the main branch on GitHub?
5. Ask it to push. If GitHub asks you to sign in, do that yourself (in the browser window it opens,
   or in the terminal pane, **Ctrl+`**). Don't paste a password or token into the chat.
6. Open the repository on GitHub, find the branch list, and open yours.

## Proof

Your branch visible on GitHub, with your commit on it.

## Misconceptions this exposes

- *"Pushing changes everyone's copy."* It adds your branch to GitHub. Nothing reaches the main
  branch until someone merges it, and nobody's laptop changes until they pull.
- *"Cloning is downloading."* A download is a snapshot. A clone keeps the history and knows where
  it came from, so you can push back and pull updates.
- *"Claude can sign in for me."* It shouldn't, and you shouldn't give it the means to. Sign-in is
  yours.
